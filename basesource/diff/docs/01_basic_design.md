## 2. 目的

本アプリは、2つのフォルダまたはBazaarリビジョン間の差分を、レビュー用のExcelブックとWordレポートへ変換する。

主な目的は次の通り。

- WinMergeのHTML差分レポートを変更テキストファイルごとに生成する。
- HTMLをファイル単位で読み込み、ExcelJSで1つのExcelブックへ統合する。
- 差分レビューに必要な行と手動修正用の保持行だけをExcelへ書き込む。
- 変更ファイル一覧に加え、新規C関数、新規グローバル変数、新規または拡張された構造体・共用体の仕様をWordへ出力する。
- Bazaarの任意2リビジョンを一時エクスポートし、フォルダ比較と同じ処理へ接続する。
- 重いレポート生成をElectronの画面プロセスから分離し、実行中の中止と終了時中止を可能にする。

## 3. 対象範囲

### 3.1 対象機能

| 機能 | 内容 |
| --- | --- |
| フォルダ比較 | 変更前フォルダと変更後フォルダを比較する。 |
| Bazaar比較 | 指定した変更前/変更後リビジョンを一時フォルダへエクスポートして比較する。 |
| GUI入力 | 参照ボタンとドラッグアンドドロップで入力フォルダを指定する。 |
| 設定 | C系/その他テキストの保持行数と非表示、WinMerge/Bazaar実行ファイルを保存する。 |
| WinMerge連携 | テキストファイルごとにWinMergeを非対話・最小化状態で実行し、HTMLを生成する。 |
| Excel統合 | HTMLを1ファイルずつ解析し、ExcelJSのストリーミングWriterで1ブックへ統合する。 |
| Word出力 | 変更ファイル一覧、新規関数仕様書、新規変数仕様書を1文書へ出力する。 |
| C言語解析 | Tree-sitter C WASMで変更前後の`.c`/`.h`を解析し、差分仕様と限定的な呼び出し元（直接識別子呼び出し/関数内`static`/`const`関数ポインタテーブル登録）を求める。 |
| 中止 | 画面の中止操作、ウィンドウ終了、アプリ終了から実行中ジョブを停止する。 |
| 出力保護 | ExcelとWordを一時名へ生成し、両方の完成後にまとめて確定する。 |

### 3.2 対象外

| 項目 | 理由 |
| --- | --- |
| バイナリ差分内容のExcel化 | バイナリはWinMerge HTMLのソース差分対象にしない。 |
| WinMerge HTML/CSSの完全再現 | 対応するHTML要素と単純CSSの範囲で変換する。 |
| Cプリプロセッサの完全評価 | Tree-sitter構文木、整数定数式、既知の型情報を利用するが、コンパイラと同一の前処理は行わない。 |
| 間接呼び出しの呼び出し元解決 | 直接の識別子呼び出しと、関数内`static`/`const`関数ポインタテーブルへの登録を対象とする。通常の関数ポインタ変数呼び出し、マクロ経由、型情報が必要な動的ディスパッチは対象外とする。 |
| MSVC ABIの完全再現 | Wordへ出すサイズは実装済みのMSVC 32bitレイアウト規則で算出し、不確定な型は「算出不可」とする。 |

## 4. システム構成

本アプリはElectronのRenderer、Preload、Mainと、`utilityProcess.fork()`で起動する専用Workerから構成する。

| 構成要素 | 責務 |
| --- | --- |
| Renderer | 入力、設定ダイアログ、実行/中止、進捗とログの表示 |
| Preload | Rendererへ型付きIPC APIを公開 |
| Main | ダイアログ、設定保存、ジョブ所有権、Worker起動、中止、終了調停 |
| Worker | Bazaar export、差分収集、WinMerge、Excel、C解析、Word生成 |
| Core | HTML解析、行選別、出力トランザクション、Cモデル/型レイアウト等の純粋処理 |

重処理をWorkerへ分離することで、RendererとMainのイベントループをレポート生成処理から分離する。

## 5. 利用シナリオ

1. 利用者がフォルダ比較またはBazaar比較を選ぶ。
2. 比較元を指定する。
3. 必要に応じて設定ダイアログを開き、保持行数、保持行の非表示、外部ツールを設定する。
4. ExcelとWordの保存先を指定する。
5. 実行する。
6. MainがWorkerを起動し、進捗を画面へ転送する。
7. WorkerがExcelとWordを一時出力へ生成する。
8. 両出力が完成した場合だけ最終ファイルへ確定する。
9. 利用者は処理中に中止できる。処理中に画面またはアプリを閉じた場合も、中止完了を待って終了する。

## 6. 画面設計概要

### 6.1 メイン画面

| 領域 | 内容 |
| --- | --- |
| ヘッダ | アプリ名、設定、実行、中止 |
| 入力モード | フォルダ / Bazaar |
| フォルダ入力 | 変更前フォルダ、変更後フォルダ |
| Bazaar入力 | リポジトリ、変更前リビジョン、変更後リビジョン |
| 出力 | Excel保存先、Word保存先 |
| 状態 | 実行フェーズ、進捗、完了/失敗/中止 |
| ログ | 新しいメッセージを先頭に表示 |

実行中および中止処理中は入力と設定を無効にする。実行中は中止ボタンを表示し、中止要求後は重複操作を無効にする。

### 6.2 設定ダイアログ

| グループ | 設定 |
| --- | --- |
| C系ファイル | 表示・保持行数、手動修正用保持行の非表示 |
| その他のテキストファイル | 表示・保持行数、手動修正用保持行の非表示 |
| 外部ツール | WinMergeU.exe、Bazaar/Breezy実行ファイル |

保持行数は0以上の安全な整数だけを受け付ける。

## 7. 設定設計

設定はElectronの`userData/settings.json`へ保存する。

| 設定 | 既定値 |
| --- | --- |
| C系ファイルの表示・保持行数 | `100` |
| C系ファイルの保持行を非表示 | 有効 |
| その他テキストの表示・保持行数 | `100` |
| その他テキストの保持行を非表示 | 有効 |
| WinMerge | `C:\Program Files\WinMerge\WinMergeU.exe`、次に`C:\Program Files (x86)\WinMerge\WinMergeU.exe`を検出し、未検出時は空 |
| Bazaar/Breezy | `brz` |
| 最終出力ディレクトリ | 空 |

`.c`と`.h`にはC系設定を適用し、それ以外のテキストにはその他設定を適用する。

## 8. Excel出力設計

### 8.1 ブック

| 項目 | 内容 |
| --- | --- |
| 形式 | `.xlsx` |
| 生成ライブラリ | ExcelJSストリーミングWriter |
| シート | 変更テキストファイルごとに1シート |
| シート名 | ファイル名を基準に一意化し、Excel禁止文字と31文字制限を処理 |
| 先頭行 | WinMergeの左右ファイルヘッダ |
| E1 | `■OK □NG` |
| フォント | `MS Gothic` |
| 変更前/変更後パス | `【変更前】$/...`、`【変更後】$/...` |
| 空側 | `【変更前】ファイルなし`または`【変更後】ファイルなし` |

Microsoft Excel、Excel COM、PowerShellはブック生成に使用しない。

### 8.2 ファイル単位処理

WinMerge HTML本文はジョブ全体で保持しない。Excel出力時にHTMLファイルを1件読み込み、解析、行選別、シート書き込み、シートcommitまで行ってから次のHTMLへ進む。

### 8.3 行選別

保持行数を`N`とする。

- 構造行は保持する。
- `.c`では、差分を含む関数全体を表示対象とし、差分を含まない関数は表示対象から外す。
- `.c`の関数外、`.h`、その他テキストでは、差分行から前後の未変更空行までと、その空行の外側`N`行を表示対象とする。
- 表示対象範囲をさらに前後`N`行へ広げ、その追加分を手動修正用保持行とする。
- 表示対象にも保持行にも入らない行は、Excel行を作る前に除外する。
- 保持行は設定が有効な場合だけExcelの`hidden`行とし、表示対象行は非表示にしない。

追加・削除行を含む差分判定には、WinMerge HTMLのソースセルまたはリッチテキストの背景色を使用する。

## 9. Word出力設計

Word文書は次の3章で構成する。

1. 変更ファイル一覧
2. 新規関数仕様書
3. 新規変数仕様書

### 9.1 変更ファイル一覧

- テキスト/バイナリを含む全変更ファイルを`$/相対パス`で出力する。
- 追加は`【新規】`、削除は`【削除】`を付ける。
- 変更された`.c`では、変更/新規/削除関数をファイル行の下へ字下げして出力する。

### 9.2 新規関数仕様書

- 変更後側の`.c`にだけ存在する関数を対象とする。
- 宣言、戻り値型、引数、Doxygen説明、戻り値、注意、警告を表形式で出力する。
- 変更後側の全`.c`/`.h`を解析対象にし、その中の関数定義から新規関数への直接識別子呼び出しと、関数内`static`/`const`関数ポインタテーブル登録による呼び出し元を求める。
- 呼び出し先が一意でない場合は「呼び出し先特定不可」とする。

### 9.3 新規変数仕様書

- 変更後側の`.h`にだけ存在するグローバル変数を出力する。
- 新規struct/unionは全メンバーを出力する。
- 既存struct/unionは変更後に追加されたメンバーだけを出力する。
- 型、配列数、総要素数、サイズ、コメントを出力する。
- サイズはMSVC 32bit規則、既定pack 8、ファイル順の`#pragma pack`を反映して算出する。
- `stdint.h`の固定幅整数型、`size_t`、`ptrdiff_t`、`intptr_t`、`uintptr_t`はシステムヘッダを解析せずMSVC 32bitの既知型として扱う。
- 外部型、曖昧な型、値再帰、VLA、フレキシブル配列、ビットフィールド等で確定できない値は「算出不可」とする。

## 10. 外部連携

| 外部要素 | 用途 |
| --- | --- |
| WinMerge | `/noninteractive /minimize /u ... /or report.html`でHTML生成 |
| Bazaar/Breezy | `export -r revision outputDir repository`でリビジョン展開 |
| ExcelJS | HTML解析結果を`.xlsx`へストリーミング出力 |
| docx | Word文書生成 |
| web-tree-sitter / Tree-sitter C WASM | C構文解析 |

WinMergeとBazaar/Breezyは`windowsHide`で起動する。中止時は本ジョブが起動したプロセスツリーだけを終了する。

## 11. 中止・終了設計

- Rendererの中止要求はMainを経由して対象Workerへ送る。
- Workerは`AbortController`を使い、外部プロセス、差分収集、Excel、C解析、Wordの各境界で中止を検出する。
- Windows上の外部プロセスは`taskkill /T`を使用し、必要時は`/F`へ移行する。
- Workerが中止要求へ応答しない場合、Mainは5秒後にWorkerを強制終了する。
- 実行中にウィンドウまたはアプリを閉じた場合、最初の終了イベントを保留し、中止と後処理の完了後に終了する。

## 12. 出力トランザクション

- ExcelとWordは最終ファイルと同じディレクトリのジョブ固有`.tmp`名へ生成する。
- 両方の一時出力が存在することを確認してから、既存出力を`.bak`へ退避し、一時出力を最終名へ昇格する。
- 2ファイル目の昇格等で失敗した場合は、昇格済み出力を除去し、既存出力を復元する。
- 中止、Worker異常終了、アプリ終了時は、開始前の出力存在状態を基にバックアップ復元または新規出力除去を行う。
- 通常終了後は`.tmp`、`.bak`、作業ディレクトリを削除する。

## 13. 非機能要件

| 分類 | 要件 |
| --- | --- |
| 応答性 | 重処理をutility processへ分離し、画面操作と進捗更新を維持する。 |
| メモリ | HTMLをファイル単位で処理し、選別外行をExcelへ書き込まない。 |
| 一貫性 | ExcelとWordをトランザクションとして確定し、片方だけの更新を避ける。 |
| 配布性 | Tree-sitter runtime WASMとC grammar WASMをアプリ資産へ同梱する。 |
| 保守性 | Worker、ジョブ管理、行選別、C解析、型レイアウト、文書出力を分離する。 |
| OS | Windowsを主対象とする。 |

## 14. 制約事項

- HTML変換品質は対応HTML/CSS範囲に依存する。
- C構文エラーは診断として保持するが、コンパイラと同一の意味解析は行わない。
- 呼び出し元解析は直接識別子呼び出しと、関数内`static`/`const`関数ポインタテーブル登録を対象とする。通常の関数ポインタ変数呼び出し、マクロ経由、型情報が必要な動的ディスパッチは対象外とする。
- 同名の非static関数が複数ある場合は呼び出し先を一意に割り当てない。
- バイナリはExcel対象外だが、Wordの変更ファイル一覧には含める。
