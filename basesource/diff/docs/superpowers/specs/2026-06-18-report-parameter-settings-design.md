# 差分レポート パラメータ設定設計

## 1. 目的

大量のWinMerge HTMLをExcel化した際に、数千から数万行のシートが複数生成され、ブックを開くまで長時間掛かる問題を軽減する。

Excelへ全行を書き込んだ後に行を削除するのではなく、HTML解析後かつExcel書込み前に出力対象行を確定する。レビュー対象から十分離れた行はExcelへ書き込まず、パースずれなどを手動修正するための周辺行だけを保持する。

あわせて、次の項目をアプリの設定として永続化する。

- C系ファイルの保持行数と保持行の非表示有無
- その他のテキストファイルの保持行数と保持行の非表示有無
- WinMerge実行ファイルの既定パス
- Bazaar/Breezy実行ファイルの既定パス

## 2. 対象ファイル区分

| 区分 | 対象 |
| --- | --- |
| C系ファイル | `.c`、`.h` |
| その他のテキスト | バッチ、スクリプト、Markdown、設定ファイルなど、C系以外の全テキストファイル |
| バイナリ | Excel差分シートの対象外。既存どおりWord変更一覧には記載する |

大文字・小文字を区別せず拡張子を判定する。

## 3. 設定画面

### 3.1 配置

メイン画面右上に歯車アイコンの設定ボタンを配置する。ボタンを押すとモーダル形式の「パラメータ設定」ダイアログを開く。

WinMergeとBazaar/Breezyの実行ファイル欄はメイン画面から設定ダイアログへ移す。通常のレポート作成画面には、入力元、出力先、実行状況だけを表示する。

### 3.2 設定項目

| グループ | 項目 | 初期値 |
| --- | --- | --- |
| C系ファイル | 表示・保持行数 | `100` |
| C系ファイル | 手動修正用の保持行を非表示にする | 有効 |
| その他のテキスト | 表示・保持行数 | `100` |
| その他のテキスト | 手動修正用の保持行を非表示にする | 有効 |
| 外部ツール | WinMergeU.exe | 既知のインストール先を自動検出。検出できない場合は空 |
| 外部ツール | bzr.exe / brz.exe | `brz` |

表示・保持行数は0以上の整数とする。負数、小数、空文字、JavaScriptの安全な整数範囲外は保存できない。

### 3.3 操作

- 「保存」で入力値を検証し、設定ファイルへ保存してダイアログを閉じる。
- 「キャンセル」または閉じるボタンで編集内容を破棄する。
- 実行ファイル欄は直接入力と参照ボタンの両方を使用できる。
- レポート実行開始時点の設定値をジョブへ渡し、実行中の設定変更によって処理内容が変わらないようにする。
- WinMergeパスが空の場合は実行不可とする。
- Bazaar比較ではBazaar/Breezyパスが空の場合も実行不可とする。

## 4. 行分類

### 4.1 用語

| 分類 | Excel出力 |
| --- | --- |
| 表示対象行 | 出力し、常に表示する |
| 手動修正用保持行 | 出力し、設定に応じて非表示または表示する |
| 出力対象外行 | Excelへ書き込まない |
| 構造行 | ファイルパスヘッダなど。出力し、常に表示する |

設定値を以降 `N` と表記する。同じ `N` を「未変更空行到達後の追加表示行数」と「表示対象前後の手動修正用保持行数」の両方に使用する。

### 4.2 Cヘッダファイル

1. 差分行を表示対象にする。
2. 各差分行から前後へ走査し、未変更の空行に到達するまで表示対象にする。
3. 未変更の空行に到達した後、さらに各方向へ `N` 行を表示対象にする。
4. すべての表示対象範囲を統合する。
5. 統合後の表示対象範囲を各方向へさらに `N` 行拡張し、追加された行を手動修正用保持行にする。
6. それ以外のコード行を出力対象外にする。

### 4.3 Cソースファイル

関数範囲の既存解析規則を維持する。

- 差分を含む関数は、関数ヘッダを含む関数全体を表示対象にする。
- 差分を含まない関数は表示対象にしない。
- 関数外の差分は、Cヘッダファイルと同じ「未変更空行まで＋N行」の規則で表示対象にする。
- 上記を統合した表示対象範囲を各方向へ `N` 行拡張し、追加された行を手動修正用保持行にする。
- 拡張時は関数境界で停止しない。WinMergeまたは軽量C解析のパースずれを手動修正できるよう、隣接する関数の行も保持対象にできる。
- 表示対象行と手動修正用保持行以外は出力対象外にする。

### 4.4 その他のテキストファイル

関数解析は行わない。Cヘッダファイルと同じ規則を適用する。

1. 差分行を表示対象にする。
2. 各差分行から前後へ走査し、未変更の空行に到達するまで表示対象にする。
3. 未変更の空行に到達した後、さらに各方向へ `N` 行を表示対象にする。
4. 統合した表示対象範囲を各方向へ `N` 行拡張し、追加された行を手動修正用保持行にする。
5. それ以外のデータ行は出力対象外にする。

### 4.5 境界条件

- `N = 0` の場合、未変更空行到達後の追加表示と手動修正用保持を行わない。
- 表示対象範囲または保持範囲がファイル先頭・末尾を超える場合は、存在する行までに切り詰める。
- 複数の表示対象範囲、保持範囲が重なる場合は統合する。
- 表示対象行は保持行より優先し、非表示にしない。
- HTMLのファイルパスヘッダなど、ソースデータ行ではない構造行は削除せず表示する。
- 追加・削除ファイルも同じ規則で処理する。WinMergeが差分として色付けした行を差分行とする。
- 出力対象外行の省略を示す行は挿入しない。A/C列の元行番号の飛びで省略箇所を確認できる。

## 5. Excel書込み方式

### 5.1 採用方式

HTMLを1ファイルずつ解析した後、ExcelJSへ行を追加する前に各HTML行を分類する。

1. WinMerge HTMLを `HtmlReport` へ解析する。
2. ファイル区分に対応する設定を選択する。
3. 各行を表示対象、手動修正用保持、出力対象外、構造行に分類する。
4. 表示対象、手動修正用保持、構造行だけをExcelJSへ追加する。
5. 手動修正用保持行へ、設定に応じて `row.hidden = true` を設定する。
6. 出力した行だけを対象に列幅を計算する。

Excelへ全行を書き込んだ後の `deleteRows` は使用しない。これにより、出力対象外セルの生成、書式設定、共有文字列処理、行削除を避ける。

### 5.2 維持する情報

- WinMerge由来の行番号
- 差分色とシンタックス色
- リッチテキスト
- ファイルパスヘッダ
- 変更前・変更後の列構成
- E1のレビュー欄
- 追加・削除ファイルの「ファイルなし」表示

Excelの物理行番号は省略行数に応じて詰まるが、A/C列のソース行番号は変更しない。

### 5.3 Excel出力経路の一本化

Excel出力は、次の本番経路だけを残す。

```text
WinMerge HTMLファイル
  → WinMerge高速HTMLパーサ
  → 行分類
  → ExcelJSストリーミング書込み
  → xlsx
```

次の旧経路は削除する。

- Excel COMでHTMLを開き、ワークシートを移動するPowerShell経路
- HTML文字列を全件メモリ上で受け取る非ストリーミングExcelJS経路
- Excel生成後に全行を走査して行を非表示にする経路

Excel COM、Microsoft Excel、PowerShellは、ブック生成の実行時依存関係としない。外部プロセス実行機能はWinMergeとBazaar/Breezyで引き続き使用する。

## 6. データ構造

`AppSettings` に次の設定を追加する。

```ts
interface RowOutputPolicy {
  contextRows: number;
  hideRetainedRows: boolean;
}

interface AppSettings {
  winMergePath: string;
  bazaarPath: string;
  lastOutputDirectory: string;
  rowOutput: {
    cFiles: RowOutputPolicy;
    otherTextFiles: RowOutputPolicy;
  };
}
```

`StartJobRequest` と `GenerateDiffWorkbookInput` に行出力設定のスナップショットを渡し、Excelエクスポーターまで伝播する。

既存の `settings.json` に `rowOutput` がない場合は両区分へ初期値を補完する。ネストした設定は階層ごとに既定値とマージし、旧バージョンの設定ファイルとの互換性を維持する。

Excel出力で共有する `HtmlReportFile`、`PathReplacement`、`ExportReportsWorkbookInput` は `src/core/workbookTypes.ts` へ移す。型定義が削除対象の実装モジュールに依存しない構造にする。

## 7. モジュール構成

| モジュール | 変更内容 |
| --- | --- |
| `src/shared/ipcTypes.ts` | 設定型、ジョブ要求型を拡張 |
| `src/main/index.ts` | 既定値、設定正規化、保存、ジョブへの設定伝播 |
| `src/renderer/src/App.tsx` | 設定ボタン、設定ダイアログ、保存・キャンセル |
| `src/renderer/src/uiText.ts` | 日本語ラベル、入力エラー文言 |
| `src/renderer/src/styles.css` | モーダル、設定グループ、数値入力のスタイル |
| `src/core/reportRowSelection.ts` | C系・その他を統一して行を表示、保持、除外へ分類する |
| `src/core/workbookTypes.ts` | Excel出力で共有する入力型を保持する |
| `src/core/excelExporter.ts` | HTMLファイル入力とストリーミング出力だけを残し、分類結果に従って必要な行だけを書き込む |
| `src/core/reportJob.ts` | 行出力設定をエクスポーターへ渡す |
| `src/core/cRowVisibility.ts` | 新しい行分類モジュールへ置換後に削除 |
| `src/core/excelComExporter.ts` | Excel COM経路と埋込みPowerShellスクリプトを完全削除 |
| `tests/core/excelComExporter.test.ts` | Excel COM専用テストを削除 |

行分類はExcelJSに依存させず、HTMLレポート行とポリシーから分類結果を返す純粋関数として実装する。

`src/core/processRunner.ts` はWinMergeとBazaar/Breezyのバックグラウンド実行に必要なため維持する。PowerShell固有のテスト名や説明は、汎用的なWindowsプロセス出力の文字コード処理として整理する。

## 8. 不要コードの削除方針

### 8.1 削除対象

- `src/core/excelComExporter.ts`
- `tests/core/excelComExporter.test.ts`
- `exportReportsWorkbookWithExcel`
- Excel COM用マニフェスト生成
- 埋込みPowerShellスクリプト
- `powershellPath`などExcel COMだけが使用する入力項目
- 非ストリーミング版 `exportReportsWorkbook`
- 非ストリーミング版だけが使用する `WorkbookReport` と `ExportReportsWorkbookInput`
- 旧 `computeHiddenCReportRows`
- 固定値 `CONTEXT_ROWS_AFTER_UNCHANGED_BLANK`
- Excel COMを補助実装として扱う設計書、テスト設計書、ビルド・リリース手順書の記載

### 8.2 移行対象

- 非ストリーミング版を利用するExcel出力テストは、一時HTMLファイルを作成してストリーミング版を呼び出す形へ移行する。
- C行非表示テストは、行分類の純粋関数テストとExcel出力結果テストへ分割する。
- `HtmlReportFile`など現行でExcel COMモジュールに置かれている共通型は `workbookTypes.ts` へ移す。
- 色、行番号、リッチテキスト、パス置換、ファイルなし表示、列幅、レビュー欄の既存回帰テストは維持する。

### 8.3 削除判定

削除前に `rg` とTypeScriptビルドで参照箇所を確認する。削除後は次の条件をすべて満たすことを確認する。

- ソースとテストにExcel COM実装へのimportがない。
- ブック生成コードにPowerShell起動処理がない。
- Excel出力APIがHTMLファイル入力のストリーミング版だけである。
- 旧固定3行ロジックが残っていない。
- 設計書類が実装済みの単一経路と一致する。

## 9. エラー処理

- 設定値が不正な場合はダイアログ内に日本語でエラーを表示し、保存しない。
- 設定ファイルが存在しない、または読込みに失敗した場合は既定値を使用する。
- 設定ファイルの一部項目が欠落している場合は、その項目だけ既定値を補完する。
- 外部ツール実行エラーは既存どおりジョブログへ表示する。
- 出力対象行がない場合でも構造行とE1レビュー欄を持つシートを生成する。

## 10. テスト方針

### 10.1 単体テスト

- C系とその他で異なる `N` が適用される。
- 未変更空行到達後に正確に `N` 行が表示対象になる。
- 表示対象の前後に正確に `N` 行が手動修正用として保持される。
- 保持範囲の外側は分類結果に含まれない。
- `hideRetainedRows=true` の場合だけ保持行が非表示になる。
- `N=0`、ファイル先頭・末尾、範囲重複を処理できる。
- Cソースの差分あり関数は全体表示、差分なし関数は表示対象外になる。
- Cソースの保持範囲は関数境界を越えられる。
- その他のテキストは関数解析せず同じ空行規則を使用する。
- 旧形式の設定ファイルに新しい既定値が補完される。
- 不正な設定値が保存されない。

### 10.2 Excel出力テスト

- 出力対象外行がワークシートに存在しない。
- 保持行の表示・非表示が設定どおりになる。
- 省略後もA/C列の元行番号、セル色、リッチテキストが維持される。
- ストリーミング出力で全行書込み後の削除処理を行わない。
- すべてのExcel出力テストがHTMLファイル入力のストリーミングAPIを使用する。
- Excel COMおよび非ストリーミングAPIの専用テストが存在しない。

### 10.3 UIテスト

- 設定ボタンでダイアログを開ける。
- 保存で設定を反映し、キャンセルで編集を破棄する。
- C系とその他を個別に編集できる。
- WinMergeとBazaar/Breezyの参照ボタンを使用できる。
- 不正な行数では保存できず、エラーが表示される。

### 10.4 負荷確認

`local-samples/load-c-diff` を使用し、次を比較する。

- 生成時間
- 出力ブックサイズ
- 各シートの出力行数
- Excelでブックを開くまでの時間

既存の15分以内というブック生成目標を維持し、今回の処理によってExcel書込み時間が大幅に増加していないことを確認する。

## 11. 文書更新

基本設計書、詳細設計書、テスト設計書、ビルド・リリース手順書を実装結果に合わせて更新する。

- Excel COM補助実装とPowerShell生成処理の記載を削除する。
- Excel出力経路をExcelJSストリーミング版だけにする。
- 行非表示中心の説明を、書込み前の表示・保持・除外分類へ変更する。
- C系とその他の個別パラメータ、設定ダイアログ、旧設定ファイル互換を追記する。
- 実行環境にMicrosoft Excelが不要であることを明記する。

- Word変更一覧の仕様書章追加。本項目は `2026-06-18-worker-c-specification-design.md` で扱う
- バイナリファイルのExcelシート化
- 省略位置を示す専用行やアウトラインの追加
