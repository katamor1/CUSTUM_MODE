# パステストレポート設計

## 1. 目的

既存のWinMerge差分Excelとは別に、C言語の変更済み既存関数および新規関数について、テスト確認が必要な行だけに確認欄を付けたパステストExcelを生成する。

既存差分Excelの行番号、左右のソース、シンタックス色、行内差分色、ファイルパスヘッダ、列幅などを流用し、確認対象外の関数やシートを除外してブックを軽量化する。

## 2. 出力物

1回の実行で次の3ファイルを生成する。

- 既存の差分Excel
- 既存のWord変更一覧・仕様書
- 新規のパステストExcel

GUIに「出力パステストExcel」の保存先を追加する。パステストExcelは既存差分Excelとは別ファイルとする。

3ファイルは同一の出力トランザクションで扱う。中止または失敗時には、新旧ファイルが混在した状態や一時ファイルを残さない。

## 3. 対象ファイル

パステストExcelの対象は拡張子が`.c`のテキストファイルだけとする。

次は対象外とする。

- `.h`ファイル
- バイナリファイル
- 削除されたCファイル
- Cファイル内の関数外だけに変更がある場合
- `#define`、`#pragma`、グローバル変数、型定義など関数外の変更

対象となるソースシートが1枚もない場合は、Excelが少なくとも1枚の可視シートを必要とするため、例外として「対象なし」シートを1枚作成し、`A1`に「パステスト対象となる変更はありません。」と表示する。このシートはソース由来シートではなく、E列の確認欄も持たない。

## 4. 対象関数

対象関数は次のいずれかとする。

- 変更前と変更後の両方に存在し、実行コードまたは分岐条件が変更された既存関数
- 変更後に新規追加された関数

次は対象外とする。

- 削除関数
- コメントだけが変更された関数
- 空白、改行、インデントだけが変更された関数
- E列の確認欄が1件も付かない関数

関数の判定と範囲取得にはTree-sitter Cパーサーを使用する。関数名だけでなく、変更前・変更後それぞれの開始行と終了行を保持する。

## 5. シート構成

シート名は既存差分Excelと同じ重複回避済みシート名を使用する。

列構成も既存差分Excelと同じとする。

| 列 | 内容 |
| --- | --- |
| A | 変更前の行番号 |
| B | 変更前のソース |
| C | 変更後の行番号 |
| D | 変更後のソース |
| E | テスト確認欄 |

各シートには次の行だけを出力する。

- 1行目のファイルパスヘッダ
- E列の確認欄が1件以上ある対象関数の、関数宣言先頭から閉じ波括弧まで

関数間の関数外行は出力しない。対象関数の途中にあるコメント行は、関数の構造を保つためA～D列には残すが、E列は空欄とする。

関数単位でE列の確認欄を判定し、確認欄が0件なら関数全体を削除する。シート内の全関数が削除対象なら、そのシート自体を作成しない。

## 6. 書式

A～D列は既存差分Excelと同じHTML解析結果から生成し、次を維持する。

- WinMergeの行番号
- 変更前・変更後の対応行
- 追加、削除、変更の背景色
- C言語のシンタックス色
- 行内差分の文字色および背景色
- `MS Gothic`を基本とする等幅フォント
- ファイルパスの`【変更前】$`、`【変更後】$`表記
- 列幅、罫線、折り返し
- 1行目の固定

E列の確認欄は`■OK □NG`とする。

- `E1`は空欄
- コメント行は空欄
- 確認対象外のコード行は空欄
- 既存差分Excelの`E1`仕様は変更しない

## 7. 確認欄の付与規則

### 7.1 変更済み既存関数

変更前と変更後を構文単位で比較し、次の変更後側の行に`■OK □NG`を付ける。

- 実行文が追加または変更された行
- 分岐条件が追加または変更された行
- 分岐経路が追加または変更された行

削除だけの行については、対応する変更後側の直後の実行可能行または分岐行に確認欄を付ける。対応先を一意に決められない場合は、所属する最小の分岐文または関数入口に付ける。

コメント、空白、関数ヘッダコメントの変更だけでは確認欄を付けない。

### 7.2 新規関数

新規関数では、関数入口と各分岐経路を確認できる位置に`■OK □NG`を付ける。

- 関数本体の開始行
- `if`
- `else if`
- `else`
- `switch`
- 各`case`
- `default`
- `for`
- `while`
- `do-while`
- 条件演算子を含む実行行

同じ行が複数の規則に該当しても、確認欄は1つだけ付ける。条件演算子の真側と偽側が同じソース行にある場合も、その行に1つだけ付ける。

### 7.3 コメントの扱い

Tree-sitterのコメントノード範囲に含まれる行には確認欄を付けない。

複数行コメント、連続する行コメント、`/********/`のような仕切りコメントもコメントとして扱う。コメントの直後に実行コードがある場合は、その実行コードの行を独立して判定する。

## 8. データ処理

1. 変更ファイルを走査する。
2. WinMerge HTMLをファイルごとに生成する。
3. HTMLを1回解析し、書式付きの行モデルを作る。
4. 同じ行モデルから既存差分Excelを生成する。
5. `.c`ファイルの変更前・変更後をTree-sitterで解析する。
6. 関数範囲、関数状態、コメント範囲、制御構文範囲を取得する。
7. WinMerge行番号とCソース行番号を対応付ける。
8. 関数ごとの確認欄位置を算出する。
9. 確認欄がある関数だけを既存行モデルから抽出する。
10. 確認欄があるシートだけをパステストExcelへ書き込む。
11. Word出力を生成する。
12. 3ファイルをまとめて確定する。

HTMLまたは完成済みExcelを再読込して複製する方式は使用しない。大容量レポートでの処理時間とメモリ増加を避けるため、解析済み行モデルを共有する。

## 9. コンポーネント

### Cパス解析

新規モジュールで次を担当する。

- 関数の追加、変更、削除判定
- コメントだけの変更の除外
- 制御構文と分岐経路の抽出
- 確認欄を付ける変更後ソース行番号の算出

### パステスト行選択

次を担当する。

- WinMerge行とソース行の対応付け
- 対象関数の関数宣言から閉じ波括弧までの抽出
- E列確認欄の付与
- E列がない関数とシートの除外

### Excel出力

既存Excel出力の行書式処理を共通化し、通常差分ブックとパステストブックで共有する。パステストブック側だけが行選択結果とE列確認欄を受け取る。

### GUI・IPC・ワーカー

次を追加する。

- パステストExcel保存先の選択
- ジョブ要求・結果への出力パス追加
- パステストブック生成フェーズの進捗表示
- 完了ログへの出力先表示

### 出力トランザクション

既存のExcel、WordにパステストExcelを加えた3ファイルを、バックアップ、昇格、ロールバック、割込み復旧の対象とする。

## 10. エラー処理

- C解析に失敗したファイルはパステストExcelへ誤った結果を出さず、ジョブを失敗させて既存出力を復元する。
- WinMerge行番号と関数範囲が対応できない場合も同様に失敗させる。
- 出力先3件には同一パスを指定できないようGUIとジョブ境界で検証する。
- 中止要求はC解析、行選択、Excel書込みの各ループで確認する。
- 既存出力がある場合は3ファイルすべてをロールバック可能にする。

## 11. テスト用サンプル

Git管理外の`local-samples`に、変更前・変更後のC言語サンプル差分を作成する。

対象確認用の`.c`には次を含める。

- 単純な実行文変更
- `if`
- `if / else`
- `else if`
- 入れ子の`if`
- `switch / case / default`
- `for`
- `while`
- `do-while`
- `break`
- `continue`
- 早期`return`
- 条件演算子
- 論理AND・ORを含む条件変更
- 新規関数
- 削除関数
- コメントを含む変更関数

除外確認用に次を含める。

- ヘッダファイルだけの変更
- グローバル変数宣言だけの変更
- `#define`だけの変更
- `#pragma`だけの変更
- 関数外コメントだけの変更
- 関数内コメントだけの変更
- 空白、改行、インデントだけの変更

## 12. テスト方針

### 単体テスト

- 既存関数と新規関数の抽出
- 削除関数の除外
- コメントだけの変更の除外
- 各制御構文の確認欄位置
- コメント行に確認欄が付かないこと
- E列がない関数の削除
- E列がないシートの除外
- `.h`の除外
- 関数外の変数、`#define`、`#pragma`変更の除外
- WinMerge行番号とソース行番号の対応

### Excel出力テスト

- `E1`が空欄
- A～D列の値、リッチテキスト、背景色、罫線、列幅が通常差分ブックと一致
- 対象行だけに`■OK □NG`がある
- コメント行のE列が空欄
- 対象外関数と対象外シートが存在しない
- 対象ソースシートが0枚の場合だけ「対象なし」シートが存在する
- 新規ファイルの変更前側表示が既存差分書式と一致

### 統合テスト

- フォルダ比較から3ファイルが生成される
- Bazaarリビジョン比較から3ファイルが生成される
- 中止、失敗、強制終了後に3ファイルが整合して復旧される
- サンプル差分の全分岐と全除外条件が期待どおりになる

### 負荷確認

既存の負荷試験サンプルを使用し、通常差分Excel生成に対してHTMLや完成済みExcelの再読込が追加されていないことを確認する。パステストExcelの行数とシート数が対象関数だけに削減され、Excelを開く時間が通常差分ブックより短いことを確認する。

## 13. 完了条件

- GUIから3つの出力先を指定して実行できる。
- パステストExcelが既存Excelとは別ファイルで生成される。
- 対象は変更済み既存関数と新規関数だけである。
- 変更または追加された実行経路・条件に確認欄がある。
- `E1`とコメント行には確認欄がない。
- 確認欄がない関数とシートは出力されない。
- `.h`、関数外変更、コメントだけの変更、削除関数が除外される。
- C言語の主要な分岐を含むGit管理外サンプルがある。
- 単体、統合、ビルドテストが成功する。
- 生成したExcelを値と見た目の両方で確認済みである。
