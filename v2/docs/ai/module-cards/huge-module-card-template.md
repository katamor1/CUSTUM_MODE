# Huge Module Card Template

このテンプレートは、Class C: 巨大 / カーネル系モジュール向けに使用する。

例:

- 1 DLL 内に多数のスレッドエントリポイントがある
- DLL 外 export 関数が 100 近く存在する
- DLL 内 extern 関数が 1000 近く存在する
- グローバル変数領域が数十 MB 以上ある
- 共有メモリ、バックアップ、複数 DLL、複数スレッドが密結合している

通常の Module Card に全情報を詰め込むと巨大化して使えなくなるため、Top Module Card は「地図 + 索引 + 危険標識」に限定する。

# 06_change_risk_map.md

## 目的

巨大 DLL では仕様説明よりも、変更時に触ると危険な場所を明示することが重要である。

## Change Risk Map

| Risk ID | リスク領域 | 理由 | 関連カード | 変更時の必須確認 | 危険度 |
|---|---|---|---|---|---|
| R-INIT | 初期化順に依存する領域 | 初期化前参照、二重初期化、終了後参照 | `05_initialization_shutdown.md` | 起動・終了テスト | 高 |
| R-THREAD | 複数スレッドから読み書きされる領域 | 競合、排他漏れ、タイミング依存 | `01_thread_index.md`, `04_global_data_areas.md` | 排他・負荷・長時間テスト | 高 |
| R-EXPORT | 複数 DLL から呼ばれる export API | 呼び出し元の暗黙仕様が壊れる | `02_export_api_index.md` | 呼び出し元 DLL の回帰確認 | 高 |
| R-SHM | 共有メモリ構造体 | レイアウト互換性、他 DLL 参照 | `04_global_data_areas.md` | 構造体サイズ・メンバ順確認 | 高 |
| R-BACKUP | バックアップ対象構造体 | 保存・復元互換性 | `04_global_data_areas.md` | 旧データ復元テスト | 高 |
| R-NOLOCK | 排他なし参照データ | 再現困難なタイミング不具合 | `04_global_data_areas.md` | 参照タイミング確認 | 高 |
| R-PASTBUG | 過去不具合多発箇所 | 回帰リスク | 不具合履歴 | 回帰テスト | 高 |

## AI レビュー時の重点観点

```text
この巨大 DLL の変更をレビューするときは、以下を重点確認する。

1. 変更対象がどの thread / api / data area に属するか
2. 複数スレッドから read-write されるデータか
3. export API の呼び出し元 DLL に暗黙仕様がないか
4. 共有メモリ / バックアップ構造体のサイズ・レイアウト互換性を壊していないか
5. 初期化前参照、終了後参照、二重初期化が起きないか
6. 排他なし参照やロック粒度変更によるタイミング不具合がないか
7. 既存の機能テストだけでなく、DLL 間連携・異常系・回帰テストが必要か
```

| 共有メモリ | レイアウト、互換性、read-write 方向 |  | `04_global_data_areas.md` | 高 |

## AI テスト観点生成プロンプト

```text

2. 複数スレッドからの read-write 競合
3. export API 呼び出し元 DLL への回帰影響
4. 共有メモリ / バックアップ構造体の互換性
5. 初期化順・終了順・異常終了時の確認

7. 最低限必要な機能テスト、異常系テスト、DLL 間連携テスト
```
