### Class C 判定

以下に該当する場合は、`huge-module-card-template.md` へ切り替える。

- [ ] スレッドエントリポイントが多数ある
- [ ] export 関数が数十〜百単位で存在する

- [ ] グローバル領域が巨大で、構造体メンバ単位の列挙が現実的ではない
- [ ] 共有メモリ / バックアップ / 複数スレッド / 複数 DLL が密結合している
- [ ] このカードが「地図」として読めないほど肥大化する見込みがある

## 8. 変更リスク

### 触ると危険な領域

- [ ] 初期化順に依存する領域
- [ ] 終了順に依存する領域
- [ ] 複数スレッドから読み書きされる領域
- [ ] 共有メモリ構造体
- [ ] バックアップ互換性に関わる構造体
- [ ] サイズ変更が危険な構造体
- [ ] 複数 DLL から呼ばれる export API
- [ ] 排他なしで参照されているデータ
- [ ] 起動直後 / 終了直前に触る処理
- [ ] 過去不具合が多い処理

### 変更時の確認事項

| 観点 | 確認内容 | 必須 |
|---|---|---|
| 呼び出し元 | 影響を受ける DLL / 関数を確認する | yes / no |
| 共有データ | read / write の向きと排他を確認する | yes / no |
| 初期化順 | 初期化前参照、二重初期化、終了後参照を確認する | yes / no |
| 互換性 | 構造体サイズ、保存形式、共有メモリレイアウトを確認する | yes / no |
| テスト | 単体、機能、異常、回帰、DLL 間連携を確認する | yes / no |

AI にこのカードを渡す場合は、変更対象に応じて以下を追加する。

- 関連ソースファイル

- 関連 Data Card
- 過去不具合 / 変更履歴
- 対象差分

### 推奨プロンプト

```text
以下の Module Card と関連ソースを前提に、変更対象の影響範囲を調査してください。
特に、呼び出し元・呼び出し先、共有メモリ、グローバルデータ、初期化順、異常系、DLL 間 I/F、テストが必要な箇所を確認してください。
```
