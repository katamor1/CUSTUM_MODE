# Command-backed Workflow AI Provider

Phase 12-13 allows workflow AI generation and repair to be delegated to an external VS Code command.

## Setting

Configure the command id with:

```json
{
  "workflowRegister.aiProviderCommand": "myExtension.workflowAiProvider"
}
```

When this setting is empty, workflow-register falls back to the deterministic mock provider.

## Command contract

The configured command receives exactly one argument:

```ts
type Request =
  | { kind: "design"; payload: WorkflowAiDesignInput }
  | { kind: "improve"; payload: WorkflowAiRepairInput }
  | { kind: "explain"; payload: WorkflowAiExplainInput }
```

The command returns one of:

- `WorkflowDesignDraft` for `kind: "design"`
- `WorkflowRepairProposal` for `kind: "improve"`
- `WorkflowDiagnosticExplanation` for `kind: "explain"`

## Design request

Example input:

```json
{
  "kind": "design",
  "payload": {
    "goal": "Review changed workflow files and produce a report.",
    "preferredTemplate": "review-workflow",
    "workspaceHints": []
  }
}
```

Example output:

```json
{
  "name": "review-workflow-files",
  "title": "Review Workflow Files",
  "description": "Review changed workflow files and produce a report.",
  "template": "review-workflow",
  "notes": ["Generated by external AI provider."]
}
```

## Improve request

Example input:

```json
{
  "kind": "improve",
  "payload": {
    "filePath": ".bob/workflows/sample/WORKFLOW.md",
    "workflowText": "...",
    "repairContext": {
      "filePath": ".bob/workflows/sample/WORKFLOW.md",
      "status": "invalid",
      "problems": []
    }
  }
}
```

Example output:

```json
{
  "summary": "The workflow references an unknown state key.",
  "notes": ["Add resultKey to an earlier step."],
  "replacementMarkdown": "..."
}
```

`replacementMarkdown` is never applied automatically. It is validated and previewed only if valid.

## Explain request

Example input:

```json
{
  "kind": "explain",
  "payload": {
    "filePath": ".bob/workflows/sample/WORKFLOW.md",
    "repairContext": {
      "filePath": ".bob/workflows/sample/WORKFLOW.md",
      "status": "invalid",
      "problems": []
    }
  }
}
```

Example output:

```json
{
  "summary": "Explained 1 workflow diagnostic.",
  "items": [
    {
      "message": "Step 'analyze' includeState references unknown resultKey 'context'.",
      "explanation": "The step reads state that no earlier step produces.",
      "likelyFix": "Add a matching resultKey to an earlier step.",
      "repairTarget": "steps[].includeState"
    }
  ]
}
```

## Output validation

The command output is considered untrusted.

workflow-register validates provider output before using it:

- design output must be an object
- draft `name` and `description` are required
- `template` must be one of the known workflow templates
- repair `notes` must be an array of strings
- `replacementMarkdown` must be a string when present
- explanation `items` must be an array
- explanation items must include `message` and `explanation`
- long strings are truncated before use

Invalid provider output fails the command and prevents saving or previewing generated content.

## Safety rules

External providers must follow these rules:

1. Do not write workflow files directly.
2. Return structured provider output only.
3. Let workflow-register run builder and validator gates.
4. Do not assume replacement Markdown will be applied.
5. Include concise notes explaining any proposed repair.
